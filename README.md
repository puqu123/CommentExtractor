# CommentExtractor · 评审意见提取

Windows 桌面工具，将 Word、Excel、PowerPoint 中的标准批注整理到 Excel；基础功能可离线使用。
v0.2.6 另支持开发编写的“编号意见＋截图”Word 评审正文，可选择被评审原始 Word 辅助定位。
源文件只读。可选配置内部模型辅助定位截图；只有启用时才会向配置的服务发送截图和候选原文。可分别导出每个勾选文件，例如 `设计说明.docx` → `设计说明_评审意见提取.xlsx`；也可把勾选文件汇总为一份 Excel。
遇到同名结果自动增加序号，不覆盖已有输出。

主程序文件名为 `CommentExtractor-v版本号-win64.zip`；带 `ocr-addon` 的是可选扩展，`-source.zip` 是源码包。其他版本见 [Releases](https://github.com/puqu123/CommentExtractor/releases)。

v0.2.25 主程序与可选 OCR 扩展分开下载，每份严格小于 **100,000,000 字节（100 MB）**：

GitHub 从 v0.2.13 直接更新到 v0.2.25；此前本地迭代的 v0.2.14–v0.2.24 不单独发布。保留 Windows 原生文件／文件夹选择窗口，格式支持范围与已知限制见下文。

## 快速上手

1. 完整解压 Windows ZIP，运行 `CommentExtractor.exe`。
2. 自带标准批注的 Word / Excel / PPT，点击“添加文件”或“添加文件夹”；正文写编号意见与截图的 Word，点击“评审 Word ＋ 原手册…”。
3. 新导入文件默认勾选。取消不需要的文件，或用顶部“全选文件”切换全部／取消全部；点击文件只切换查看，不改变勾选。
4. “是否接受”可填是、否、重复，也可以留空。提取内容在程序中只读。
5. 点击“分别导出”，每个勾选文件各生成一份 Excel；或点“汇总导出”，把勾选文件的意见放入一份 Excel。有失败时查看“处理记录”。

完整操作见 [简明使用说明](USAGE.md)。免安装包内同时附有 `USAGE.txt`，可直接双击阅读。

## 开发评审 Word 正文（v0.2.6）

点击“评审 Word ＋ 原手册…”，分别选择开发评审 Word 和原手册，再按需填写评审人。支持 `.docx` 和通过 Microsoft Word 转换 `.doc` 副本。原手册可放在任意目录，只用于辅助定位。一次选择的文件共用原手册和评审人，不同手册／不同评审人请分批导入。普通“添加文件”仍只读取标准批注。

- 按 `1、`、`1.`、`1）`、`（1）` 或 Word 顶层自动编号分条。本条编号至下一条编号之间的文字、多张图片和截图后的补充内容归为一条意见。嵌套自动编号留在本条，复杂表格、文本框、浮动图片及特殊编号仍需真实样例验证。
- 评审正文原样放入“评审意见”。截图 OCR 和匹配到的原文放入“对应原文／内容”；原始图片另存附件。单击“上下文截图”列查看本条全部图片，预览中双击截图放大。
- 每张截图分别匹配原手册，位置优先展示章节或图表标题及 Word 排版页码；目录样式的条目不参与匹配。正文多处匹配时逐行列出各处位置；截图识别的页码单独标为待核对。无法识别则写“位置未确定”，不把评审 Word 自身的页码当成被评审文档页码。
- 导入窗口可选择 Windows 离线 OCR 或 RapidOCR 离线增强识别。两者均在本地运行；还可选用配置的模型辅助定位。识别失败仍保留意见和原图，识别结果需核对。

- 不使用作者／最后修改人猜测评审人；该入口的评审人由导入时指定或留空。正文中的答复仍作为原文保留，不自动猜测回复关系。
- 原始 `.docx` 没有可直接信赖的实时排版页码。普通批注使用章节标题和可搜索选区定位，不显示“正文第几段”。程序自动通过本机 Microsoft Word 对临时副本排版，并按匹配段落附上页码；开发评审必须提供原手册。未获取页码时明确提示，不推算页码。不同 Word/WPS、字体及打印设置可能改变分页。

### 可选内部模型

在主界面“模型设置”填写公司提供的 OpenAI 兼容服务地址（含 `/v1`）和 API Key，点击“获取可用模型”后从服务返回列表中选择模型；若接口没有提供模型列表，也可手动填写 ID。点击“测试连接”可分别检查文本接口和读图能力，测试仅发送程序生成的内容。密钥使用当前 Windows 用户加密保存。开发评审导入中可勾选“使用 AI 辅助定位”；已配置时默认勾选，可取消。启用后会把截图、OCR 文字及最多 20 条候选原文发送至所配置地址，请确保地址和公司数据使用规则符合要求。不上传整本手册。服务失败或结果无效时保留本地匹配结果；AI 位置需要人工核对。每个程序实例最多约每分钟 28 次请求，不能控制其他用户共享的服务额度。使用不可信 HTTP 网络时内容可能被截获，优先使用公司提供的 HTTPS。

生成虚构样例：`python scripts/make_developer_samples.py`，输出在 `local_data/CommentExtractor-v0.2.11-开发评审测试`，附测试步骤；不要公开上传公司原始文件。

## 阅读与填写

桌面端支持拖放文件或文件夹、后台批量提取、文字筛选和批量导出。
底部横向进度条显示处理阶段和百分比，覆盖解析、OCR 和 Excel 写入；阶段耗时不均，百分比不是剩余时间预测。
Excel 位置显示为“检查表 · B2”，合并单元格显示为“检查表 · B2:D3”。长原文在列表中以 `.....` 缩略，双击对应单元格可查看／复制全文，导出保留全文。
拖动表头边界调整列宽，拖动左侧行号边界调整行高；拖动文件列表与表格之间的分隔条调整两侧宽度。
界面默认列顺序与 Excel 导出一致；窗口较窄时，可横向滚动查看后面的评审意见和回复。
格式提示仅占一行，完整说明位于“处理记录”，不会随合并文件增多挤占表格。
对应原文、评审人、评审意见、回复等提取内容在程序中只读。
仅“是否接受”可以人工选择是、否、重复；可以留空直接导出，后续在 Excel 中填写。
程序不保存项目或工作进度，填写接受情况后请先导出，再关闭或清空列表。

## 多文件批量导出

1. 点击“添加文件”，在同一个文件夹中按 Ctrl 或 Shift 选择任意组合的 Word、Excel、PPT 文件。
2. 也可以点击“添加文件夹”导入该目录及子目录中的全部受支持文件，或直接拖入多个文件／文件夹。
3. 提取完成后，可按需填写“是否接受”，无需逐条确认即可导出。
4. 勾选需要导出的文件。顶部“全选文件”支持全选／取消全选，部分勾选时显示中间状态；新导入文件默认勾选。
5. “分别导出（N份）”：选择输出目录，每个勾选且成功提取的文件各生成一份 Excel。“汇总导出（1份）”：选择保存位置和文件名，将这些文件的全部意见汇总到一份 Excel。

两种导出都以复选框为范围，不受当前查看文件或意见搜索筛选影响；不再设置单独的合并按钮。只导出一部分文件后，其余文件中未导出的接受情况仍会在关闭／清空前提示。汇总导出不改变左侧文件列表，之后还可重新勾选、分别导出。

顶部“清除文件”只移除程序列表里的勾选项，不删除硬盘原文件；如果要移除的文件有未导出的接受情况，程序会先提示。

程序没有设置 5 个或 6 个文件的数量上限，实际容量取决于内存和文件大小；已验证 12 份同名文件独立导出。
列表会保留提取失败的文件，导入时提示跳过／失败原因；导出完成报告计划数、成功数、失败数、未处理数。
“处理记录”可查看逐文件结果，不再自动生成批量结果 TXT。超过 Excel 文字上限的内容仍会保存为完整文本附件，避免丢失。
只能传文字时，选中异常文件后使用“处理记录 → 脱敏诊断（可复制）”。报告包含统一错误码、构建标识及结构计数，不含文档文件名、路径、姓名、意见、正文或截图；先预览并按公司规则审核。疑似漏提取但没有报错时也可使用。步骤及错误码见 [文字反馈说明](SUPPORT.md)。

不同评审人的主意见分别保留为独立行，各自关联源文件中已有的回复，不按姓名合并意见。
源文件更新或需要换一批文件时点击“清空列表”重新导入。
没有可读取批注的文件仍可导出空汇总表，并在“提取报告”中注明；提取失败的文件不会导出为空表。

## 同一文档收到多份 peer review

例如 `A文件_rev by wwl.docx` 和 `A文件_rev by zsl.docx`：

1. 一次导入这两个文件，保持左侧复选框勾选。若还有其他手册，取消勾选不需要的文件。
2. 点击“汇总导出（1份）”，在 Windows 保存窗口填写 `A文件_评审意见提取.xlsx`。默认文件名仅供参考，勾选决定汇总范围。
3. 两位评审人的意见均保留；同一问题第一次出现可选“是／否”，后出现的相同意见选“重复”。不自动按相似文字去重。
4. 导出得到 `A文件_评审意见提取.xlsx`，左侧仍保留两份文件，不额外生成独立表；需要独立表时再点击“分别导出”。

汇总表为 10 列，新增“文件名”列，每行显示实际来源的评审返回文件（含扩展名）。重复行不删除，保留另一位评审人的记录；“提取报告”通过公式统计重复数和去除重复后的意见数，打开 Excel 时计算。
因此无论“是否接受”在工具里还是 Excel 中填写，重复标记都能参与后续统计。未标记的相似意见不会擅自扣除。
各条意见的完整来源路径也记录在“提取报告”中，方便核对同名文件。
界面中的“有效意见”及报告中的去重数量 = 主意见总数 − 标记为“重复”的数量；它们包含“是”“否”和未填写的意见，并非接受数。

## 导出表格

“评审汇总”固定为以下 10 列：

意见编号、文件名、位置、对应原文／内容、上下文截图、评审人、评审意见、是否接受、回复人、回复内容。

- 导出仅保留“评审汇总”和“提取报告”两个页签。一条主意见一行，回复人及完整回复按文件记录顺序放在汇总表中。
- “是否接受”默认留空，下拉可选“是、否、重复”，由人填写。
- 不自动推断人员真实身份、接受情况或整改责任人。
- “提取报告”显示数量、格式限制和警告；读取失败不会伪装成“没有意见”。
- 开发评审导入窗口可选保留文字、截图或两者，评审意见及回复正文始终保留。此配置决定导出内容，不会重新执行导入时关闭的 OCR。
- “上下文截图”保留开发评审图片及 Word 批注／回复内嵌图片；不自动截取整页或幻灯片。Excel 行高默认 60 磅，显示小缩略图；点击单元格文字打开本地截图列表，可逐张打开原图。原图在同名附件目录。普通 `.xlsx` 不含双击放大宏；软件预览内支持双击放大。移动 Excel 时必须带上附件目录，否则链接失效。
- 超过 Excel 单元格长度上限或含不可表示控制字符的文字保存在 TXT 附件，避免静默截断。
- 再次导出会生成新结果，不会读取或合并用户在旧 Excel 中的手动修改。

## 格式支持与当前边界

| 格式 | 已实现 | 当前限制 |
|---|---|---|
| `.docx` | 标准批注、选区文字、commentsExtended 回复关系、批注内嵌图片、标题与搜索短句；开发评审正文及截图 | 可选 Microsoft Word 排版页码；未启用或不可用时保留标题／搜索短句；特殊对象／厂商扩展需真实样例验证 |
| `.doc` | 通过本机 Microsoft Word 将临时副本转换后读取标准批注 | 必须安装并可正常使用 Microsoft Word；不支持仅装 WPS 的转换，复杂旧格式仍需核对 |
| `.xlsx` | 旧式便笺、现代评论和回复、工作表与单元格、内容 | 公式优先读已保存缓存，缺失时显示公式，不执行计算；图片便笺不做 OCR |
| `.pptx` | 传统／现代批注、现代回复、幻灯片顺序；编号冲突恢复和分部件容错 | 暂无对象原文定位、幻灯片渲染和截图；传统批注无明确回复关系时作为独立意见 |

不支持旧版 `.xls/.ppt`，请先另存为新格式。标准 `.docx/.xlsx/.pptx` 解析与 OCR 不依赖 Office；`.doc` 转换和自动 Word 页码依赖 Microsoft Word。
v0.2.8 对没有回退分支的新版 Excel 辅助扩展尝试保留可读内容，并明确标注兼容恢复；不能据此保证所有未知扩展中的意见均已读取。照片中的 CE-E206 原文件尚无法核验。
v0.2.5 已通过 28 项自动检查及 Windows 打包程序的导出／启动验证；构造样例不能代替 Office、WPS 等真实文件的兼容性验证，尤其是现代批注扩展。
v0.2.6 修复传统 PPT 不同作者使用相同批注编号导致整份提取失败的问题。异常重复编号会重新编号并保留所有批注；回复指向重复编号时独立保留，不随意绑定。损坏部件跳过并在处理记录／提取报告标明“部分提取”，可读部件继续导出；全部批注部件均无法读取时仍报告失败，不生成虚假的空成功表。批量处理继续执行其他文件。
兼容性用例、逐条内容核对和 Office/WPS 真实保存验收见 [兼容性测试方案](COMPATIBILITY.md)。构造用例、异常恢复与预期失败分别统计，不能据此宣称所有 Office/WPS 文件 100% 兼容。可运行 `python scripts/check_compatibility.py` 生成带独立预期的构造文件、结果及人工核对清单。
PDF 已移出需求范围，解析库和页面预览代码已移除。
大文件仍受内存限制；Office 压缩包内单个部件解压后超过 128 MiB 时，当前版本会报告不支持。这不是整个源文件大小的上限。

## 署名准备

评审前在 Office 的“文件 → 选项 → 常规”设置本人用户名；现代账户型评论需检查登录账户显示名。
新建批注及回复后保存、关闭、重开，确认署名正确。修改默认设置不会自动修复历史错误署名。

## 开发运行

已验证的开发环境为 Windows x64、Python 3.9.13；其他 Python 版本尚未验证。使用免安装包时不需要 Python。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe run_app.py
```

源码需要增强 OCR 时，另执行 `python -m pip install -e ".[ocr]"`；构建完整的两份发布包使用 `.[dev,ocr]`，构建脚本会自动安装这些依赖。

### 命令行与测试样例

```powershell
.\.venv\Scripts\python.exe scripts\make_samples.py
.\.venv\Scripts\python.exe -m commentextract.cli .\local_data\demo -o .\output
.\.venv\Scripts\python.exe -m pytest -q
```

开发评审命令行示例：

```powershell
.\.venv\Scripts\python.exe -m commentextract.cli 开发评审.docx --developer-word --reference 原始文档.docx --reviewer 王工 -o .\output
# 不识别截图文字，但保留截图附件
.\.venv\Scripts\python.exe -m commentextract.cli 开发评审.docx --developer-word --no-ocr -o .\output
# 增强 OCR、原手册排版页码，以及文字与图片一起导出
.\.venv\Scripts\python.exe -m commentextract.cli 开发评审.docx --developer-word --reference 原手册.docx --ocr-backend rapidocr --word-pages --content-mode both -o .\output
```

命令行会跳过输出目录内的输入文件、Office 临时文件和经表头验证的本工具导出表，并报告原因；输出目录请选在输入目录之外。
仅文件名含 `_评审意见` 的原始文档不会被直接排除。命令行在终端显示结果；桌面版可在“处理记录”查看结果。

样例生成在 `local_data/demo`，包括六份 Office 虚构文件，不使用真实评审数据。
真实文件也请放在 `local_data`，该目录已被 Git 忽略。公开前仍应检查待提交文件列表。

### Windows 免安装打包

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1
```

生成 `dist/v<版本号>/CommentExtractor/CommentExtractor.exe`，以及主程序 ZIP、可选 OCR 扩展 ZIP 和校验文件。打包脚本分别检查两份 ZIP 的实际字节数，任一达到 100,000,000 字节就停止；不会输出超限的新包。不同版本使用独立目录，避免覆盖正在运行的旧版。
使用时解压整个 ZIP，再运行 EXE；不能只拷贝 EXE。
文件选择、导入文件夹和输出目录选择均调用 Windows 原生窗口，使用系统的导航栏、图标和交互，不附加应用主题或自定义图标提供器。
未处理的界面异常会弹出提示，错误日志保存在 `%LOCALAPPDATA%\CommentExtractor\logs\app.log`。
程序不自更新。基础功能不上传文档；启用 AI 辅助定位时会向用户配置的服务发送截图和部分原文。企业电脑是否允许运行取决于终端管理策略。

### 后续版本发布

修改 `commentextract/__init__.py` 和 `pyproject.toml` 中的版本号，更新 `CHANGELOG.md` 并提交代码后，可以继续让 Codex 发布。
已有 GitHub CLI 凭据有效时无需重复设备授权。也可以自己运行脚本：

```powershell
# 只查看将要发布的仓库和版本，不上传
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\publish_release.ps1
# 测试、构建和验证后发布为预发布版
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\publish_release.ps1 -Publish
```

脚本会推送 main 和版本标签，创建带主程序 ZIP、源码 ZIP、SHA256 校验文件的 Release，不覆盖已有版本；兼容时复用 v0.2.11 的 OCR 扩展链接，发布前验证扩展的文件指纹和兼容性。
运行前应已安装开发依赖、配置 origin 并登录官方 GitHub CLI；默认保持预发布标记，明确使用 `-Stable` 才按正式版发布。
图标源文件位于 `commentextract/assets/app.svg`，修改后运行 `python scripts/build_icon.py` 可重新生成 PNG 和多尺寸 ICO。
